# IP 투자 적대적 심사

심사는 분석가들이 만든 낙관을 깎아 내는 단계다. 남은 근거만으로 판정해야 판정 회의가 판정문을 믿을 수 있다. CIPO의 2번 과제(무엇에 추가 투자할까)에 답한다. 심사위원이 내는 등급은 **초안**이고, 결정은 사람이 한다.

## 1. 스크리닝(후보 여러 개 → 심층 진단 우선순위)

후보 카드마다 네 기준으로 상·중·하를 매긴다.

| 기준 | 질문 |
| --- | --- |
| 남은 확장 여지 | 아직 하지 않은 포맷 중 적합도가 높은 것이 있는가 |
| 신호 강도 | 규모·몰입·해외 신호가 A·B등급 출처로 확인되는가 |
| 사업 간 협업 가능성 | 스토리·뮤직·미디어·공연·아티스트가 함께 움직일 지점이 있는가 |
| 판단 시급성 | 지금 판단하지 않으면 잃는 것이 있는가(시즌 재개, 경쟁 제안, 계약 만료). 이미 모든 확장이 끝난 IP는 낮다 |

후보마다 `심층 진단` / `관찰` / `제외`와 한 줄 이유, 선정을 반박하는 가장 강한 논거 한 줄을 쓴다. 전체 순위를 정할 때는 고른 이유가 "이미 성공했으니까"가 아닌지 확인한다. 그런 후보는 기준점으로만 남긴다.

## 2. 주장 추출

최종 판정 전에 분석 파일(확장 지도·글로벌 진단·권리 점검·내부 신호)에서 **판단에 영향을 주는 주장**을 모두 뽑는다.

- 판단에 영향을 준다: 포맷 적합도 점수, 확장 순서, 시장 적합도, 권리 확보 우선순위, 뒤집기 조건의 근거가 되는 문장
- 뽑지 않는다: 배경 설명, 이미 확인된 기본 정보(원작자, 연재 시작일)
- 한 문장에 주장이 둘이면 나눈다. 숫자가 들어간 주장은 숫자를 그대로 둔다.
- `core: true`는 이 주장이 무너지면 등급이나 포맷 판정이 바뀌는 주장에만 붙인다.

`30_judge_claims.md`에 표(`id | 주장 | 출처 파일 | 근거로 든 것 | core`)로 쓰고 같은 목록을 반환한다. id는 `P-01`(확장 지도), `G-01`(글로벌), `R-01`(권리), `D-01`(내부 신호)처럼 출처를 앞에 붙인다.

## 3. 주장 검증(evidence-verifier)

검증자는 `references/claim-verification.md`를 따른다. 오케스트레이터의 워크플로가 검증 결과를 다음 규칙으로 **제안 분류**한다.

| 제안 분류 | 조건 |
| --- | --- |
| 통과 | 모든 관점이 `confirmed`이고 가장 강한 출처가 A·B등급 |
| 기각 | 어느 관점이라도 `refuted` |
| 조건부 | 그 밖의 모든 경우(검증 결과 없음 포함) |

## 4. 최종 판정

1. **분류 확정**: 제안 분류를 받아 최종 분류를 정한다. 바꾸면 `바꾼 이유`에 근거를 적는다. 검증 결과가 없는 주장은 통과로 올리지 않는다.
2. **반대 논거**: 통과한 core 주장 가운데 가장 중요한 세 개에 가장 강한 반대 논거를 쓴다.
3. **충돌 정리**: 분석끼리 엇갈린 판단(예: 해외 첫 영상이 실사냐 애니냐)은 양쪽 근거를 나란히 놓고 택한 쪽과 이유를 쓴다.
4. **등급 판정**: 아래 등급표를 쓴다. 포맷별 판정도 따로 낸다.
5. **뒤집기 조건**: 어떤 내부 데이터나 권리 확인 결과가 나오면 등급이 오르거나 내리는지, 누가 언제 확인할 수 있는지 적는다.
6. **90일 권고와 하지 말 것**: 해야 할 일과 하지 않을 일을 함께 쓴다.

## 5. 등급표

| 등급 | 의미 | 조건 |
| --- | --- | --- |
| A — 즉시 확장 | 1차 확장을 바로 기획에 넣는다 | core 주장 대부분 통과, 1차 확장 권리 확인 가능성이 높음 |
| B — 조건부 확장 | 확인 사항 2~3개가 풀리면 진행 | core 주장이 조건부, 신호는 강함 |
| C — 관찰 | 신호를 더 모은다 | 근거가 구조 추론 위주 |
| D — 보류 | 지금은 투자하지 않는다 | core 주장 기각, 또는 권리상 실행 불가 |

포맷별 판정은 같은 A~D에 `실행됨`(이미 한 확장), `판단 보류`(근거 없음)를 더해 쓴다. 해외 포맷의 B는 수요가 확인됐다는 뜻이 아니라 "적은 비용으로 잴 수 있다"는 뜻일 수 있다. 그렇다면 그렇게 적는다.

## 6. 판정문 형식

```markdown
# {IP명} 투자 심사 판정 ({YYYY-MM-DD}, {n}차{, 부분 심사})
## 한 줄 판정
> {등급} · {의미} — {이유 한 문장}
## 포맷별 판정
| 포맷 | 판정 | 핵심 이유 | 뒤집기 조건 |
## 주장별 심사
| id | 주장 | 제안 분류 | 최종 분류 | 바꾼 이유 | 근거·메모 |
- 합계: 통과 {n} · 조건부 {n} · 기각 {n}, 제안 분류를 바꾼 주장 {n}
## 가장 강한 반대 논거 3개
## 분석 간 충돌과 택한 쪽
## 판정을 뒤집을 확인 사항
| 방향(올림·내림) | 확인 사항 | 이렇게 나오면 | 바뀌는 판정 | 누가·언제 확인 |
## 확장 순서(심사 후)
## 90일 실행 권고
## 90일 안에 하지 않을 것
## 판정 변경(2차 이상)
## 이 판정의 한계
- 사용한 데이터(공개 자료 / 공개 + 내부 지표), 사람의 검토 여부, 권리 가정
```

한 줄 판정과 포맷별 판정은 판정서에 글자 그대로 옮겨진다. 짧고 단정하게 쓰되 하방 조건("다만", "~전까지는")을 빼지 않는다.

## 7. 블라인드 판정(사후 검증)

blind-panelist가 `judge` 렌즈로 이 스킬을 쓸 때는 검증자가 없다. 주장 추출과 분류를 판정단이 직접 하되, 근거는 블라인드 신호 카드 안에서만 찾는다. 신호 카드의 출처 등급 표기를 그대로 쓰고, 원문을 열지 못했다는 사실을 한계에 적는다.
