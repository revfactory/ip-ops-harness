# 내부 집계 지표 분석

공개 자료로 끝내 채울 수 없던 칸이 있다. 조회수는 독자 수가 아니고, 완독률·재방문율·국가별 열람은 플랫폼 안에만 있다. 이 스킬은 그 칸을 채우되, 제안서가 약속한 데이터 원칙(작품 단위 비식별 집계만, 승인 전에는 외부 AI에 넣지 않음)을 **스크립트로 강제**한다.

## 1. 데이터를 열기 전에

1. `policy/data-approval.md`가 승인 상태인지 스크립트가 확인한다. 직접 판단하지 않는다.
2. 원본 CSV를 Read로 열지 않는다. 스크립트가 개인 식별 열을 막고 소수 셀을 숨긴 뒤의 출력만 쓴다.
3. 스크립트가 거부하면 우회하지 않는다. 거부 사유를 그대로 보고한다.

| 종료 코드 | 뜻 | 할 일 |
| --- | --- | --- |
| 3 | 승인 없음·만료·외부 AI 전송 미허용 | 분석 중단, "보안 승인 필요" 반환 |
| 4 | 개인 식별 가능 열, 또는 행이 너무 많아 개인 단위로 보임 | 분석 중단, 플랫폼 담당에게 작품 단위 집계로 다시 받도록 요청 |
| 5 | 파일·열 형식 문제 | `references/data-schema.md`의 규약과 다른 점을 적어 반환 |

## 2. 실행

```bash
python3 .claude/skills/internal-signal-analysis/scripts/internal_metrics.py \
  --ip {ip} --data _workspace/00_input/internal/{ip} \
  --policy policy/data-approval.md --today {기준일} \
  --out _workspace/ips/{ip}/r{n}/internal_metrics.json
# 비교 IP 데이터가 있으면: --compare _workspace/00_input/internal/{비교ip} ...
```

입력 파일 규약(열 이름, 단위, 예시)은 `references/data-schema.md`에 있다.

## 3. 해석 규칙

지표는 판정의 근거일 뿐이다. 등급을 매기지 않는다. 대신 각 지표가 판정의 어느 칸에 영향을 주는지 적는다.

| 지표 | 무엇을 가르나 | 영향을 주는 판정 칸 |
| --- | --- | --- |
| 순 독자 수 | "조회수는 독자 수가 아니다"라는 단서를 푼다 | 전체 등급의 신호 강도, 대중 포맷 판정 |
| 독자 1인당 열람(누적 열람 ÷ 순 독자 수) | 장편 웹소설은 회차 수만큼 커진다. 같은 회차 규모의 비교 IP와 견줄 때만 의미가 있다. 비교 IP보다 높으면 소수 고관여 독자의 반복 열람 쪽이다 | 실사 드라마(대중) vs 애니·공연·굿즈(팬덤) |
| 완독률 | 끝까지 따라온 비율. 대중 포맷이 기대는 넓은 독자층의 근거 | 실사 드라마·영화 |
| 재방문율 | 다시 돌아오는 비율. 시즌제·회차형 포맷의 근거 | 드라마 시즌, 애니 쿨, 연재 재개 |
| 회차별 열람(1화 대비) | 초반 이탈 곡선. 3화·10화 비율은 초기 신호로 쓸 수 있다 | 발굴 단계 우선순위, 연재 중 IP의 성장 판단 |
| 국가별 열람 | 공개 자료로 한 건도 채우지 못했던 칸. 해외 서비스가 있는 IP에만 있다 | 글로벌 첫 진출 시장, 해외 포맷 판정 |

- **비교 기준이 없으면 높다·낮다를 쓰지 않는다.** "비교 IP 없음, 값만 기록"으로 적는다. 기준 없이 붙인 형용사가 판정을 움직이면 근거를 위조한 것과 같다.
- 판정문의 뒤집기 조건에 해당 지표가 있으면(예: "완독률·순 독자 수가 소수 고관여 쪽이면 실사 드라마 D") 조건 문장을 인용하고, 이번 값이 어느 쪽인지와 비교 기준이 충분한지를 함께 적는다.
- 기간이 여러 개면 가장 최근 기간을 기준값으로 쓰고 이전 기간은 추이로만 쓴다.
- **지표 정의를 적는다.** 완독률·재방문율은 회사·팀마다 정의가 다르다(`references/data-schema.md`). 데이터 담당에게 받은 정의 문장을 카드 맨 위에 그대로 적고, 받지 못했으면 "정의 미확인"으로 적어 확인을 요청한다. 정의를 모르면 IP끼리 비교하지 않는다.
- **스크립트 경고를 옮긴다.** 단위 혼재, 규약 밖 파일, 기준일 차이 같은 경고는 「확인하지 못한 것」에 그대로 옮기고 데이터 담당에게 물을 질문으로 바꾼다. 스크립트가 값을 맞췄더라도 원본의 문제는 남아 있다.

## 4. 출력 형식

```markdown
# {IP명} 내부 신호 카드 ({YYYY-MM-DD}, {n}차)
> 작품 단위 비식별 집계. 승인: {승인자}, {승인일}, 범위: {허용 범위}
> 지표 정의: 완독률 = {데이터 담당이 준 정의 또는 "정의 미확인"}, 재방문율 = {같음}
## 요약
- 3줄
## 지표
(스크립트 Markdown 출력을 그대로 붙인다)
## 판정에 주는 영향
| 지표 | 값 | 비교 기준 | 영향을 주는 판정 칸 | 방향(올림·내림·판단 보류) |
## 뒤집기 조건 대조(이전 판정문이 있을 때)
| 판정문의 조건 | 이번 값 | 충족 여부 | 메모 |
## 확인하지 못한 것(스크립트 경고, 정의 미확인 지표, 데이터 담당에게 물을 질문)
```

## 5. 하지 않는 것

- 개인 단위 로그, 회원 정보, 결제 정보를 요청하거나 분석하지 않는다.
- 원본 CSV를 다른 경로로 복사하거나 내용을 판정 문서에 옮기지 않는다. 스크립트 출력 표만 옮긴다.
- 웹 검색으로 내부 지표를 보완하지 않는다(이 에이전트에는 웹 도구가 없다).
