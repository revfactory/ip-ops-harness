# 8주 파일럿 운영(제안서 §6)

제안서의 일정과 역할을 하네스 실행으로 옮긴 표다. 기간·인원·범위는 제안값이며, 실제 승인된 값이 다르면 그 값을 따른다.

## 1. 주차별 운영

| 주차 | 쓰는 데이터 | 하네스에서 할 일 | 사람이 결정하는 것(기록) |
| --- | --- | --- | --- |
| 1–2주 | 공개 자료 | 사후 검증 쌍 후보 제시(`backtest.md` §1), 지금 방식의 판단 준비 시간 기준값을 사용자에게서 받아 기록, 권리 확인 질문 목록(1차 진단의 22 파일)을 법무에 넘길 형태로 정리 | 사후 검증 쌍, 데이터 범위와 추출 공수, 보안 승인(`policy/data-approval.md`는 사람이 쓴다) |
| 3–4주 | 공개 자료 + 이미 있는 집계 리포트 | IP 3개 1차 진단(`diagnosis.md` §2), 사후 검증 블라인드 자료·판정(`backtest.md` §2~4) | 주 1시간 판정 회의에서 1차 판정 검토 → 결정 기록 |
| 5–7주 | 비식별 집계 지표 4종 추가 | 승인된 IP만 2차 진단(`diagnosis.md` §3), 사후 검증 결과 수집과 적중표(`backtest.md` §5) | 판정 회의에서 포맷별 판정 확정 → 결정 기록 |
| 8주 | — | 최종 보고서(아래 2절) | 계속·중단·확대(CIPO) |

- 이미 있는 집계 리포트(예: 전시 티켓 판매·굿즈 매출 구성)는 리포트 파일을 `_workspace/00_input/reports/{ip}/`에 받아 리서처·분석가 입력으로 넘긴다. 개인 정보가 없는 집계 문서인지 사용자에게 확인한다.
- 카카오페이지·카카오웹툰 통합 일정과 겹치면 5–7주 단계를 미룬다. 미룬 사실을 원장 메모와 보고서에 남긴다.
- 판정 회의 참여 조직(스토리·미디어·공연·데이터)은 회의 기록을 받을 때 함께 묻고 `add-decision --note`에 적는다.

## 2. 보고서 — 실행 모드: 서브에이전트 위임

1. 메인이 재료를 모은다: `ledger.py report`, `ledger.py diff`, `ledger.py hits` 출력을 `_workspace/pilot/week{n}_ledger.md`에 저장하고, 판정서·적중표 경로 목록을 만든다.
2. 작성: `Agent(subagent_type: "verdict-writer", prompt: "verdict-dossier 스킬 「4. 파일럿 보고서」를 따른다. 재료: {목록}. 출력: _workspace/pilot/report_week{n}.md")`
3. 검토: `Agent(subagent_type: "dossier-reviewer", prompt: "verdict-dossier 스킬 references/review-checklist.md의 보고서 검토 기준으로 report_week{n}.md를 판정서·적중표 원문과 대조한다. 파일을 고치지 않는다.")` 결과를 `_workspace/pilot/review_week{n}.md`로 저장한다.
4. 높음·중간 지적이 있으면 작성자에게 한 번 고치게 한다.
5. `deliverables/파일럿_보고_{n}주차_{YYYYMMDD}.md`로 복사한다.

## 3. 측정 지표 기준값

| 지표 | 기준값 출처 |
| --- | --- |
| 판단 준비 시간(지금 방식) | 1–2주 차에 사용자가 알려 준 값. 받지 못했으면 "측정 전"으로 둔다 |
| 판단 준비 시간(시연) | 첫 시연 실측 약 56분(단계 합), 벽시계 약 57분. 사람 검토 시간 제외 |
| 심사가 깎은 주장(시연) | 36개 중 조건부 18, 기각 4 |
| 원문과 다시 맞춘 숫자·사실(시연) | 8건(고침 7, 확인 1) |

시연값은 공개 자료·사람 검토 없음 조건의 값이다. 파일럿 값과 비교할 때 조건 차이를 함께 적는다.
